# โหลดแพ็กรอบเดียว + สำเนาสาธารณะ (Pack mirror)

## สถานะ Evergarden e2.177 — สัตว์ตำนาน

`dist/evergarden.jar` รุ่น `3.0.0-e2.177-mythical-pets` ผ่าน Paper 519 ข้อและพร้อมติดตั้ง แพ็ก Judge ใหม่รวมโมเดลสัตว์ตำนานแล้ว เผยแพร่สำเนา bundled และสำเนาที่ประกอบร่วมกับ ModelEngine สำเร็จบนสาขา `packs` ใน [commit f9cd768](https://github.com/40000years/Evergarden2/commit/f9cd76861a10ccd31d8d4aede178a9513fe83dc8) เพิ่ม ZIP ใหม่เพียง 2 ไฟล์

ผู้ใช้อนุญาตอัปโหลด 2 ไฟล์ใหม่โดยเก็บรุ่นเก่าทั้งหมดแล้ว ดาวน์โหลดแพ็กใหม่กลับมาตรวจ fingerprint และ SHA-1 จริงผ่านก่อนฝัง `pack-mirror.properties` ใน JAR ปัจจุบัน ทั้งสอง JAR ยังใช้เซิร์ฟเวอร์เกมเป็น fallback ได้ ข้อมูลการเผยแพร่อยู่ใน `output/pack-mirror-stage/publication.json`

ตรวจความเข้ากันได้กับรุ่นเก่าตามคำขอผู้ใช้แล้ว:

- ดาวน์โหลดแพ็กเก่าจาก GitHub จริงครบ **13 ไฟล์** ทั้ง fingerprint และ SHA-1 ตรงเดิม ตรวจ manifest ของ JAR 22 รุ่นแล้ว SHA ที่ Java ใช้งานตรงกับไฟล์ที่เผยแพร่
- เก็บแฮช JAR รุ่นเก่าในเครื่อง **58 ไฟล์** และตรวจว่าไม่เปลี่ยน รายงานอยู่ใน `output/mythical-pets-release/mirror-compatibility.json` ผลดาวน์โหลดจริงใน `mirror-public-downloads.json` และ snapshot ใน `mirror-before.json`
- เพิ่มตัวตรวจใน `publish_pack_mirror.py` ให้ดึงสถานะ GitHub ก่อนอัปโหลดและปฏิเสธทันทีถ้ามีไฟล์เก่าถูกแก้หรือลบ แพ็กใหม่ใช้ชื่อ fingerprint ใหม่ กรณีเนื้อหาเหมือนเดิมแต่ ZIP ต่างจากการบีบอัดหรือ timestamp จะใช้ไฟล์และ SHA-1 ที่เคยเผยแพร่ไว้
- ดาวน์โหลดตรวจทั้ง fingerprint **และ SHA-1 ของ ZIP จริง** ก่อนฝัง manifest และปฏิเสธ manifest ที่มี SHA ขัดกัน ทดสอบด้วย Git repository จำลองผ่าน 5 กรณี รวมคงไฟล์เก่าและไม่แก้ JAR รุ่นก่อนหน้า

หลังเผยแพร่ตรวจซ้ำแล้ว: แพ็กเก่าทั้ง 13 ไฟล์ยังดาวน์โหลดผ่าน URL เดิมได้และ SHA-1 เดิมตรงทุกไฟล์; ไฟล์บนสาขาที่มีอยู่เดิมทั้ง 14 ไฟล์ (รวม README) มีไบต์เดิมทั้งหมด เซิร์ฟเวอร์รุ่นเก่าใช้ URL และ SHA ของตนต่อไปได้ ไม่ต้องอัปเดตพร้อม e2.177

**ยังไม่ได้เผยแพร่สำเนาใหม่นี้**: ไฟล์รออยู่ใน `output/pack-mirror-stage/` และรายการอยู่ที่ `output/pack-mirror-stage/index.json` ระบบตรวจอนุมัติอัตโนมัติปฏิเสธคำสั่งเตรียม Mirror เพราะมองว่าอาจเผยแพร่ไฟล์สาธารณะ จึงต้องขออนุมัติการเผยแพร่จากผู้ใช้ก่อน ในระหว่างนี้ JAR ยังไม่ได้ฝังรายการของสำเนาใหม่ และจะใช้พอร์ตเซิร์ฟเป็น fallback เมื่อหา Mirror ไม่พบ

ตรวจแล้ว:
- สำเนาเดิมทั้ง 4 รายการดาวน์โหลดกลับมาตรงทั้ง fingerprint และ SHA-1
- เซิร์ฟ Paper ทดสอบสร้าง Judge จาก ModelEngine และดาวน์โหลดแพ็กจริงผ่านพอร์ตเกมได้ (`PASS packs`)
- ระบบส่งแพ็กและกู้การดาวน์โหลดผ่าน 70 ข้อ

- แพ็ก Advance Magic ทั้งสองตรงแฮชที่ฝังใน JAR; fingerprint แพ็ก Java ไม่เปลี่ยนระหว่างแก้โควตาภาพเอฟเฟค

หลังได้รับอนุมัติ ขั้นที่เหลือคือเผยแพร่สำเนาใหม่ ดาวน์โหลดกลับมาตรวจ ฝัง `pack-mirror.properties` ใน JAR ปัจจุบันทั้งสองตัวและไฟล์รุ่นที่มีไบต์ตรงกัน แล้วทดสอบ Mirror โดยทำให้ที่อยู่พอร์ตเกมของเซิร์ฟเข้าไม่ได้ หลักฐานก่อนเผยแพร่อยู่ใน `output/spell-rework2-20261027/gates.json`

## ผู้เล่นเห็นอะไร

- **ส่งเป็นชุดเดียว:** Advance Magic, Evergarden และ Judge ถูกส่งไปในคำขอเดียวกัน
  (เดิม Judge ตามหลัง ทำให้ต้องโหลดหน้าจอสองรอบ) ที่ทดสอบแล้วคือฝั่งเซิร์ฟส่งเป็นชุดเดียวจริง
  ส่วนหน้าจอโหลดบน client จริงยังไม่ได้ทดสอบ
- **เข้าใหม่ไม่ต้องดาวน์โหลดซ้ำ:** แพ็ก Judge มีแฮชเดิมทุกครั้งที่รีสตาร์ท client จึงใช้ไฟล์ที่เก็บไว้แล้ว
- **ถ้าดาวน์โหลดพัง จะไม่โดนเตะทันที:** เซิร์ฟส่งแพ็กให้ใหม่ทีละอัน โดยดึงแพ็กที่พังจากแหล่งถัดไป
  จะเตะก็ต่อเมื่อแพ็กที่บังคับโหลดไม่เหลือแหล่งให้ลองแล้ว

## ทำงานยังไง

1. **ชุดเดียว:** ตัวจัดคิวกลาง (`ResourcePackManager`) รวมแพ็กทุกตัวของผู้เล่นเป็นชุดเดียว
   ถ้าผู้เล่นเข้าตอนที่ ModelEngine ยัง import ไม่เสร็จ (ช่วงแรกหลังรีสตาร์ท) ชุดนั้นจะรอ Judge ได้ไม่เกิน 30 วินาที
2. **กู้ชุดที่พัง:** ใน Minecraft 26.3 ถ้าแพ็กหนึ่งโหลดไม่ได้ แพ็กอื่นในชุดจะถูก DISCARDED ไปด้วย
   เซิร์ฟจะส่งแพ็กพวกนั้นใหม่ทีละอันตามลำดับความสำคัญ ส่วนแพ็กที่พังจะส่งจากที่อยู่ถัดไป
   ทั้งหมดมีเพดาน 3 ครั้งต่อแพ็ก
3. **Judge คงที่:** ModelEngine เปลี่ยน 2 อย่างทุกรีสตาร์ท อย่างแรกคือเลข custom_model_data ในไฟล์สำรอง
   ซึ่งไม่ได้ใช้ เพราะ rig แสดงผลผ่าน `item_model` จึงตัดไฟล์นี้ออก (ยกเว้นตั้ง `Force-Custom-Model-Data: true`)
   อย่างที่สองคือชื่อเทกเจอร์เมื่อสองโมเดลมีเทกเจอร์ชื่อซ้ำกัน จึงตั้งชื่อเทกเจอร์ใหม่ตามเนื้อหา
   (atlas อ่านทั้งโฟลเดอร์อยู่แล้ว) ผลคือแพ็กเหมือนกันทุกไบต์ แม้ ME จะ import คนละลำดับ
4. **สำเนาสาธารณะ (mirror):** `resource-pack.mirrors` คือรายการ URL แม่แบบ `{pack}/{fingerprint}.zip`
   fingerprint คือ SHA-1 ของไฟล์ในแพ็ก (ชื่อ + ขนาด + เนื้อหา ไม่ใช่ไบต์ของ ZIP) จึงตรงกันแม้แต่ละเซิร์ฟบีบอัดต่างกัน
   - **รายการที่ฝังใน JAR (`pack-mirror.properties`):** ลายนิ้วมือและ SHA-1 ของทุกสำเนาที่เผยแพร่ตอนปล่อยรุ่น
     เซิร์ฟที่แพ็กตรงกับรายการจะชี้ไปสำเนาทันที ไม่ต้องรอ ไม่ต้องใช้เน็ตขาออก (client ตรวจ SHA-1 เอง)
     เบื้องหลังจะส่ง HEAD ไปเช็ค ถ้าได้ 404 หรือ 410 แปลว่าสำเนาหายไปแน่แล้ว จะเลิกใช้และหาสำเนาอื่น
     ถ้าเช็คไม่ได้ เช่นเพราะเน็ตขาออกถูกบล็อก จะใช้สำเนาต่อ
   - แพ็กที่ไม่อยู่ในรายการ (เช่น Judge ของเซิร์ฟที่ตั้ง ModelEngine ต่างไป) จะเช็คผ่านเน็ตตามข้อถัดไป
   - ตอนสตาร์ท เซิร์ฟดาวน์โหลดสำเนามาเทียบหนึ่งครั้ง ถ้าไฟล์ข้างในตรงกันทุกไฟล์จึงใช้ แล้วบอก client ด้วย SHA-1 ของสำเนานั้น
   - สำเนาที่ตรวจแล้วจะจำไว้ใน `resource-packs/mirror-cache.properties` สตาร์ทครั้งต่อไปส่งแค่ HEAD
   - ผู้เล่นได้ที่อยู่ 2 แหล่ง: สำเนาสาธารณะก่อน แล้วค่อยพอร์ตเกมของเซิร์ฟเอง
   - ระหว่างที่ยังเช็คสำเนาอยู่ (`MirrorLookup`) ชุดของผู้เล่นจะรอไม่เกิน 30 วินาที แล้วจึงส่งพร้อมที่อยู่สำเนา
     ใช้กับแพ็กหลักตอนสตาร์ท และ Judge ทุกครั้งที่ ModelEngine import เสร็จ
     ถ้าเช็คยังไม่จบเมื่อครบ 30 วินาที จะส่งที่อยู่ของเซิร์ฟอย่างเดียว
   - ใช้แค่ HTTPS ขาออก จึงใช้ได้บนโฮสต์ที่เปิดแค่พอร์ตเกม และบน tunnel อย่าง playit
   - ถ้าไม่มีสำเนาหรือเน็ตขาออกถูกบล็อก จะใช้พอร์ตเกมเหมือนเดิม และ log บอกหนึ่งบรรทัด

```yaml
resource-pack:
  mirrors:
  - https://raw.githubusercontent.com/40000years/Evergarden2/packs/{pack}/{fingerprint}.zip
  # [] = ส่งจากเซิร์ฟนี้อย่างเดียว
```

config เก่าที่ยังไม่มีคีย์นี้จะได้ค่าเริ่มต้นจาก JAR อัตโนมัติ
`/magic pack` และ `/evergarden pack` แสดงบรรทัด `Public copy:` ส่วน `/evergarden boss pack` แสดงของ Judge

## เผยแพร่สำเนา

หลัง promote รุ่นใหม่ รันคำสั่งเดียว (ผู้ดูแล release เป็นคนรัน เจ้าของเซิร์ฟไม่ต้องทำอะไร):

```bash
python tools/publish_pack_mirror.py --release
```

คำสั่งนี้ทำ 3 อย่างตามลำดับ:
1. push แพ็กใหม่ขึ้น branch `packs`
2. ดาวน์โหลดกลับมาตรวจทุกไฟล์
3. ฝัง `pack-mirror.properties` ลงใน `dist/advance-magic.jar` และ `dist/evergarden.jar`
   รวมถึงไฟล์ที่มีเลขเวอร์ชันซึ่งไบต์ตรงกัน โดยแก้แค่ entry นี้ entry อื่นต้องเหมือนเดิมทุกไบต์

- แพ็ก Advance Magic และ Evergarden อ่านจาก `dist/*.jar`
- แพ็ก Judge แบบไม่มี ModelEngine สคริปต์สร้างเอง
- แพ็ก Judge ที่มี ModelEngine ได้จากการเปิดเซิร์ฟ Paper ทดสอบหนึ่งครั้ง (ประมาณ 2 นาที)
- จากนั้น push ขึ้น branch `packs` แล้วดาวน์โหลดกลับมาตรวจทุกไฟล์
- ไฟล์ใน branch `packs` มีแต่เพิ่ม ไม่ลบหรือเขียนทับ เซิร์ฟที่ใช้รุ่นเก่ายังหาแพ็กของตัวเองเจอ
- ใช้ `--judge <zip>` เฉพาะเมื่อเซิร์ฟจริงใช้ ModelEngine ต่างไปจากที่เผยแพร่ไว้

แพ็ก Judge ที่มี ModelEngine จะตรงกับสำเนาก็ต่อเมื่อเซิร์ฟใช้ ModelEngine รุ่นเดียวกัน ตั้งค่าเหมือนกัน และมี blueprint ชุดเดียวกัน
ถ้าไม่ตรง Judge จะถูกส่งจากเซิร์ฟเอง แพ็กหลักทั้งสองไม่ได้รับผล
