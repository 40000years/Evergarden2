# Six Rivers — Overworld sanctuaries

Historical e2.75 documentation. The current release is
[e2.76: furnished interiors, End City loot and expanded teleport](overworld-sanctuaries-v2.md).

15 October 2026 · Evergarden `3.0.0-e2.75-overworld-sanctuaries`

Six large, fully authored vanilla-block destinations use the supplied six-panel
reference for their architectural themes. Each includes furnished rooms, side
buildings, a processional entrance, an outdoor arena and **eight hidden single
chests**. No boss models, summoning triggers or combat are installed in this phase.
Visual similarity to the concept is a review judgment, not a measured percentage.

Open the [exterior / interior gallery](../previews/overworld-sanctuaries/index.html)
or the [six-building overview](../previews/overworld-sanctuaries/overview.png).
These are renders of the shipped block assets with simulated lighting. Interior
cutaways hide the upper architecture only in the image; they do not change the
building in Minecraft. They are not game-client screenshots.

| Acheron | Dark Forest | Gothic rose fortress, rose window, four main towers, defensive enclosure, archive wings and a throne altar |

| Cocytus | Snowy Plains | White and blue abbey, bell towers, buttresses, archives, organ pipes and an ice altar |

| Styx | Savanna | Twin-tower gate fortress, monumental double axe, barracks, tents, guard lodges and a muster court |

The authored grounds span approximately 210–220 blocks, including landscaping.
The arena's outer decorative circle is 76 blocks across. Its central **60-block
diameter has a continuous floor and 28 blocks of unobstructed headroom**. Banshee's
arena stands four blocks above the water datum. Walkable stairs and bridges join
the entrance, arena and all treasure rooms. Chest locations are tucked beside
desks, behind furnishings, in side archives and in small outbuildings. No cache
requires breaking protected walls or placing blocks to reach it.

## Installation and commands

Replace `plugins/evergarden.jar` with the release [dist/evergarden.jar](../dist/evergarden.jar)
and restart. No existing world is regenerated by the installation process.
From an ordinary Overworld, administrators can use:

```text
/sanctuary locate acheron
/sanctuary tp acheron
/sanctuary tp phlegethon
/sanctuary tp cocytus
/sanctuary tp banshee
/sanctuary tp malefeasance
/sanctuary tp styx
```

`locate` samples candidates without creating chunks. `tp` uses Paper's asynchronous
teleport and lets normal chunk generation create the destination as it is loaded.
The search visits a maximum of 24 grid rings; rare biomes may have no accepted
site in that radius. Commands and tab completion require `evergarden.admin`.

## Placement and old worlds

`overworld-sanctuaries.enabled` enables generation. The optional `worlds` list
restricts it to named worlds; an empty list permits ordinary Overworlds. Nether,
End, Evergarden and worlds using a custom generator are excluded. World settings
are saved by UUID to `plugins/Evergarden/overworld-sanctuaries.yml` before adding
the populator. The default grid is 64 chunks (1,024 blocks), with a 65% candidate
roll before biome checks. The center and eight footprint samples must match the
destination's exact biome. These are sparse landmarks; 65% is not the final rate.
The default-seed integration survey found all six kinds among 9,409 cells.

Existing region files conservatively exclude every intersecting layout cell on
first installation. This can also exclude unexplored chunks in a partially
explored cell. The exclusion is intentional: an old build must never acquire
only half a sanctuary. Those exclusions and placement settings survive restart;
changing grid/chance in config does not move a saved world's sites. Do not delete
the ledger to increase spawn rates. Sites stay outside 1,024 blocks of the origin.

The populator samples the vanilla biome provider without loading neighboring
chunks. It writes only its current 16×16 chunk. Structures fit fully inside their
cell, and absolute coordinates work on either side of zero. Foundations extend
to solid ground. Heights are fixed by kind (arena datum Y=80 normally, Y=94 for
Badlands and water datum Y=64 for Swamp); these are broad landscaped platforms,
not a terrain-following or slope-adaptive village system. Existing vanilla
structure reservations are not queried, so an otherwise accepted new site may
intersect another feature generated by Minecraft.

## Treasure and persistence

Six caches use the vanilla Simple Dungeon loot table and two use Abandoned
Mineshaft loot. Each has a seed derived from its site and cache index and a saved
`sanctuary_loot_seed` identity. Existing inventory migration may cause vanilla
loot to roll during first chunk load instead of first player interaction; both
paths persist the resulting inventory. Chunk reloads and restarts never repaint
the building or refill a looted/deleted chest. No boss-only rewards are assigned.

These buildings currently use ordinary Overworld building permissions. Dedicated
boss combat and protection policies can be attached in the later boss phase.

## Sources and verification

- Authoring: [build_overworld_sanctuaries.py](../tools/build_overworld_sanctuaries.py).
- Runtime: [OverworldSanctuaries.java](../evergarden/src/main/java/com/example/voidscape/world/OverworldSanctuaries.java).
- Assets: `evergarden/src/main/resources/overworld-sanctuaries/*.ows`; compressed
  palette plus exact block-state coordinates and eight cache positions.
- Walkability/arena validation: `python tests/overworld-sanctuaries/check_geometry.py`.
- Build: `python tools/build_overworld_sanctuaries.py`, then
  `python tools/build_overworld_release.py` (uses this workspace's cached dependencies).
- Real Paper probe: `python tests/overworld-sanctuaries/run.py --server output/<new-fixture>`.
  It creates an isolated server, checks every authored solid voxel and all eight
  caches per structure, varies chunk generation order, samples real biome-based
  placement and boots twice to verify emptied caches, exact inventories and edits.
- Preview: `python tools/preview_overworld_sanctuaries.py --minecraft-jar <client.jar>`;
  repeat with `--cutaway`, then `--assemble`. Requires NumPy and Pillow. Textures
  are read from the local client archive and are not redistributed separately.

Geometry validation is stored in `previews/overworld-sanctuaries/geometry-validation.json`.
The verified Paper 26.3 build 152 fixture at
`output/overworld-sanctuaries-paper-verified-20261015/` passed both boots: all
**1,902,006 authored blocks**, 48 reachable caches, arena headroom, persisted
loot identities, exact inventories, an emptied cache and an administrator edit.
The saved placement/exclusion ledger was byte-identical after restart.
The release manifest under `output/overworld-sanctuaries-build-20261015/` identifies
the tested JAR, assets and runtime reports. The integration fixture verifies server
generation and persistence; it is not a connected Java/Bedrock visual benchmark.
