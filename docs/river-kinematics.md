# Six Rivers — e2.82 / movement and articulated poses

ไฟล์ `dist/evergarden.jar` รุ่น `3.0.0-e2.82-river-kinematics` ใช้ ModelEngine R4.1.1
และแพ็ก Bedrock 3.30.0 ต้องรีสตาร์ตเซิร์ฟเวอร์และเข้าเกมใหม่รับแพ็ก

แก้จากคลิป Styx ที่ผู้ใช้ส่งและข้อสังเกตของทั้งหกตัว:

| ตัว | การเปลี่ยนแปลง |
| --- | --- |
| Acheron | หมุนสามรอบใน 24 tick และพุ่งไปตามทิศที่ล็อกตอนปล่อย เคลื่อนตัวรับดาเมจจริงด้วย native collision สูงสุดประมาณ 7–8 บล็อกต่อสกิล ชนกำแพงแล้วหยุด ผู้เล่นโดน spin ได้ครั้งเดียวต่อรอบ |
| Phlegethon | ยกมือสองข้างพ้นหัว รวบไฟเหนือหัว แล้วก้มลำตัวและย่อเข่าทุบพื้น มือไม่ผ่านอก/หัวระหว่างยกหรือลดลง เท้าคงตำแหน่งบนพื้น วงเตือนอยู่ตรงจุดทุบด้านหน้าประมาณ 3.2 บล็อก |
| Styx | เลิกหมุนแขนทั้งชุดแข็งรอบไหล่ ให้ขวานขับการเคลื่อนไหวแล้วแก้ข้อต่อแขนสองข้างตามตำแหน่งด้าม มือซ้ายเลื่อนจับให้ใกล้มือขวาระหว่างยก คมขวานลงด้านหน้าแทนงัดด้ามผ่านหน้า เท้าคงตำแหน่งขณะย่อและก้ม |
| Cocytus | ยืนยิงด้านข้างลำตัว 90 องศา ยื่นแขนธนูและดึงแขนสายแยกคนละด้าน เลี่ยงการพับแขนผ่านอกและหัว ใช้ตำแหน่งกระดูกมือจริงเป็นจุดปล่อยเมื่อ ME ประเมิน pose แล้ว |
| Banshee Wail | ผ้า veil/cape สะบัดไปด้านหลังตอนปล่อยเสียง พร้อมก้มตัวเล็กน้อย |
| Malefeasance | เปิดแนวแขนซ้ายออก ปรับท่ารวบพลังให้ปลายนิ้วไม่ชนหัว |

Acheron, Phlegethon และ Styx ใช้สกิลเป็นหลัก ไม่กลับไปเดินตีปกติระหว่างคูลดาวน์
ระยะเริ่มสกิลและคูลดาวน์ต่างกัน: Acheron 14 บล็อก/90 tick, Phlegethon 10/110,
Styx 12/160 โดย Styx ยังเสียหลักหลังปล่อยสกิล ส่วน Cocytus และ Malefeasance
ใช้การโจมตีไกลประกอบสกิล และ Banshee ใช้เสียงโจมตีปกติเมื่อยังไม่ใกล้รอบสกิล

ตัวติดตั้งอัปเกรด blueprint ที่ Evergarden จัดการพร้อมสำรองต้นฉบับ
หากเซิร์ฟเวอร์แก้ไฟล์ blueprint เอง ตัวติดตั้งจะรักษาไฟล์นั้นไว้และแจ้ง console
เมนู `/evergarden test` → Six Rivers ใช้ทดสอบโมเดลหรือ combat ทีละตัว
เวลาแสดง cast ในเมนูตรงกับจังหวะของแต่ละตัวแล้ว

คลิปของแม่น้ำทั้งหกตั้งเป็น `override: true` เพราะเป็นท่าเต็มสเกเลตัน
ModelEngine R4 มี idle เริ่มต้นอยู่ชั้นล่าง หากให้คลิปใหม่เป็น additive
ท่า idle ของแขน Styx จะถูกบวกซ้ำ ทำให้ตำแหน่งมือจริงคลาดจากจุดจับด้าม
แม้ตัวเลขของ bbmodel เมื่อประเมินเพียงคลิปเดียวจะถูกต้องก็ตาม

แก้การแปลงแกน translation ของ R4 เพิ่มเติมด้วย: ตัวอ่าน geometry กลับแกน X/Z
แต่ animation position กลับเฉพาะ Z จึงต้องเข้ารหัส X ของตำแหน่งแอนิเมชันกลับด้าน
เพื่อให้ขวานกับจุดจับมืออยู่ตรงกันทั้ง Java และ Bedrock
metadata `evergarden_animation_position_x` ใช้ให้ renderer/exporter ถอดกลับอย่างชัดเจน
โดยยังรองรับรูปแบบเดิมของโมเดลอื่น

## ภาพตรวจและขอบเขตการยืนยัน

`previews/river-choreography-v2/` มีภาพหน้า/ข้าง/หลังและ GIF ที่เรนเดอร์จาก bbmodel ที่ส่งจริง
`acheron-charge.gif` เพิ่มการจำลองระยะเคลื่อนตัวตามกฎ runtime บนพื้นกริด เพื่อให้เห็นการพุ่ง
ภาพเหล่านี้ไม่ใช่ภาพจับจากไคลเอนต์ Minecraft

การตรวจครอบคลุมมือ/นิ้ว/ท่อนแขนชนรูปทรงอกและหัว ทั้งช่วงเตรียม ปล่อย และคืนท่า
ใช้ oriented-box overlap พร้อมระยะยอมให้รอยต่อเกราะสัมผัสกัน 0.2 หน่วยโมเดล
สุ่ม 61 ตำแหน่งต่อคลิปของทั้งหกตัว ไม่พบการซ้อนกันที่เกินเกณฑ์
ตรวจมือเกาะแกนด้าม เท้ายึดพื้น มือยกเหนือหัว จุดทุบใกล้พื้น และผ้าสะบัดไปด้านหลังเพิ่มเติม
การทดสอบเป็นการสุ่มตัวอย่าง ไม่ใช่หลักฐานว่าทุกเฟรมทุกมุมของไคลเอนต์ไม่มีปัญหา

คำสั่งตรวจ:

```text
python tests/model-engine/check_river_body_clearance.py
python tests/model-engine/check_river_choreography.py
python tests/model-engine/check_river_assets.py
python tests/model-engine/check_bedrock_rig.py
```

ชุด Paper/ME ตรวจการนำเข้าโมเดล GUI การยิงลูกธนูจริง การพุ่งแบบขั้นย่อย
การชนกำแพง การโจมตีครั้งเดียวต่อ spin และการเก็บกวาด entity
